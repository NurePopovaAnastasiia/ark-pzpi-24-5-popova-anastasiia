3 ОПИС ВИКОНАНОЇ РОБОТИ
3.1 Важливість правил оформлення програмного коду
Правила оформлення програмного коду - це набір рекомендацій щодо структури, форматування, іменування елементів та документування програмного коду. Їх дотримання забезпечує єдиний стиль написання програм і полегшує спільну роботу розробників.
Стандартизація коду особливо важлива під час командної розробки, оскільки над одним проєктом можуть працювати декілька програмістів. Використання однакових правил дозволяє швидше розуміти чужий код, спрощує перевірку змін та зменшує витрати часу на його підтримку.
Основними перевагами дотримання правил оформлення коду є:
* читабельність – зрозуміла структура та назви елементів полегшують сприйняття програмного коду;
* підтримуваність – правильно організований код простіше змінювати, розширювати та виправляти;
* зменшення кількості помилок – послідовне оформлення допомагає швидше помічати потенційні проблеми;
* узгодженість – однаковий стиль забезпечує цілісність програмного проекту незалежно від кількості розробників.
Для мови Lua правила оформлення мають особливе значення через її гнучкість, динамічну типізацію та можливість використовувати різні підходи до організації програмного коду. Узагальнення переваг представлено на рисунку Б.3.
3.2 Структура програмного коду
Правильна структура програмного коду передбачає логічний поділ програми на окремі файли, модулі та функції відповідно до їхнього призначення.
У Lua для організації програмного коду використовуються модулі, які дозволяють розділяти функціональність програми на окремі логічні частини. Кожен модуль зазвичай зберігається в окремому файлі з розширенням .lua та відповідає за виконання певних завдань.
Наприклад, математичні операції можна винести в модуль calculator.lua, який міститиме функції додавання та множення. Для підключення такого модуля в інших частинах програми використовується функція require() [1]. Схему організації показано на рисунку Б.4.
Приклад використання функції require():
1  local calculator = require("modules.calculator")
2
3  local result = calculator.add(5, 3)
4  print(result)
Такий підхід спрощує структуру програми, полегшує підтримку коду та дозволяє повторно використовувати функції без їх дублювання. 
Повну реалізацію модуля calculator разом із його використанням наведено
в прикладі В.1 додатка В. Модуль зареєстровано через package.preload, тому
додатковий файл calculator.lua для запуску демонстрації не потрібен.
Такий підхід дозволяє розділити програму на незалежні логічні частини та повторно використовувати функції.
На відміну від деяких об'єктно-орієнтованих мов програмування, Lua не має вбудованого синтаксису оголошення класів. Об'єктно-орієнтований підхід можна реалізувати за допомогою таблиць і метатаблиць. Для визначення методів використовується синтаксис із двокрапкою (:), який забезпечує передавання об'єкта через параметр self. Практичні підходи до організації об'єктів та програмних компонентів мовою Lua також розглядаються у збірнику Lua Programming Gems [2].
Для підтримання зрозумілої структури рекомендується створювати невеликі функції, групувати пов'язану логіку в модулі та уникати надмірного використання глобальних змінних.
3.3 Форматування програмного коду
Форматування визначає зовнішній вигляд програмного коду: відступи, пробіли, перенесення рядків та розташування конструкцій. Дотримання єдиного стилю форматування сприяє підвищенню читабельності та підтримуваності програмного коду, що відповідає загальним принципам, викладеним у праці Clean Code [3].
У Lua більшість блоків коду визначаються за допомогою ключових слів then, do, function та завершуються словом end. Тому правильне використання відступів має велике значення для розуміння вкладених конструкцій.
Для оформлення коду можна використовувати два або чотири пробіли на один рівень вкладеності чи табуляцію. Єдиного обов'язкового варіанта для всіх проєктів Lua немає. У межах розглянутих прикладів використовується відступ із чотирьох пробілів. Порівняння відступів наведено на рисунку Б.5. 
Приклад неправильного форматування:
1  function check_age(age)
2  if age >= 18 then
3  print("Adult")
4  else
5  print("Minor")
6  end
7  end
Приклад правильного форматування:
1  local function check_age(age)
2      if age >= 18 then
3          print("Adult")
4      else
5          print("Minor")
6      end
7  end
Другий варіант має чітку структуру, завдяки чому легко визначити межі функції та умовного оператора.
Також рекомендується:
* використовувати однаковий тип відступів у всьому проєкті;
* розміщувати пробіли навколо операторів присвоєння та порівняння;
* розділяти логічні блоки порожніми рядками;
* уникати надмірно довгих рядків, орієнтуючись на встановлену в проекті межу, наприклад 100 символів;
* дотримуватися однакового стилю оформлення викликів функцій та умовних конструкцій.
У мовах C++ і Java для розміщення фігурних дужок можуть використовуватися стилі Allman або K&R. У Lua такі стилі безпосередньо не застосовуються, оскільки для позначення блоків використовуються ключові слова.
3.4 Правила іменування змінних і функцій
Іменування є одним із найважливіших аспектів оформлення коду. Зрозумілі назви допомагають визначити призначення змінної або функції без додаткових пояснень.
У програмуванні використовуються різні стилі іменування:
* snake_case – слова розділяються символом підкреслення;
* camelCase – кожне наступне слово починається з великої літери;
* PascalCase – кожне слово починається з великої літери;
* UPPER_CASE – великі літери, які часто використовуються для позначення констант.
Для Lua можна обрати snake_case для змінних і функцій, а UPPER_CASE – для значень, які за домовленістю не повинні змінюватися. Основні стилі іменування ілюструє рисунок Б.6.
Приклад невдалого іменування:
1  local x = 100
2  local y = 0.2
3
4  local function f(a, b)
5      return a - a * b
6  end
7
8  local z = f(x, y)
Приклад зрозумілого іменування:
 1  local product_price = 100
 2  local discount_rate = 0.2
 3
 4  local function calculate_final_price(price, discount)
 5      return price - price * discount
 6  end
 7
 8  local final_price = calculate_final_price(
 9      product_price,
10      discount_rate
11  )
У другому прикладі назви змінних і функції відображають їхнє призначення.
Окрему увагу необхідно приділяти уникненню «магічних чисел» – числових значень, призначення яких не пояснюється в коді.
Замість використання числа безпосередньо у виразі доцільно створити змінну з відповідною назвою:
1  local MAX_ATTEMPTS = 3
2
3  if attempts >= MAX_ATTEMPTS then
4      print("Limit reached")
5  end
У Lua ключове слово local обмежує область видимості змінної, але не робить її незмінною. Тому використання великих літер для умовних констант є домовленістю щодо стилю, а не механізмом захисту значення.
3.5 Коментарі в програмному коді
Коментарі використовуються для пояснення призначення окремих частин програми, складної логіки та важливих рішень розробника.
У Lua однорядкові коментарі починаються із символів --, а багаторядкові можуть записуватися за допомогою конструкції --[[ ... ]]. Приклади наведено на рисунку Б.7.
Приклад однорядкового коментаря:
1  -- Максимальна кількість спроб
2  local max_attempts = 3
Приклад багаторядкового коментаря:
1  --[[
2  Функція перевіряє можливість
3  користувача отримати доступ
4  до системи.
5  ]]
Важливо розрізняти коментарі, які пояснюють дії програми, та коментарі, які пояснюють причини певного рішення.


Надлишковий коментар:
1  -- Збільшуємо лічильник на один
2  counter = counter + 1
Такий коментар дублює очевидну дію та не надає додаткової інформації.
Корисний коментар:
1  -- Залишаємо одну додаткову спробу
2  -- для повторного введення даних.
3  local max_attempts = 4
Цей коментар пояснює причину вибору конкретного значення.
Коментарі рекомендується використовувати для пояснення неочевидної логіки, обмежень та особливостей реалізації. Водночас зрозумілий код не повинен потребувати коментаря для кожного рядка.
3.6 Документування програмного коду
Документування є процесом створення описів функцій, модулів та інших компонентів програми. Воно допомагає розробникам зрозуміти призначення коду, порядок його використання та очікувані результати.
Для різних мов програмування існують спеціальні інструменти документування, наприклад Javadoc для Java та Doxygen для декількох мов програмування.
Для Lua можна використовувати інструмент LDoc, який дозволяє створювати документацію на основі спеціальних коментарів у програмному коді. Зразок оформлення документації зображено на рисунку Б.8. 
Основні елементи документації функції:
* назва та короткий опис призначення;
* перелік параметрів;
* опис значення, яке повертається.
Приклад документування функції:
 1  local calculator = {}
 2
 3  --- Обчислює кінцеву вартість товару.
 4  -- @param price Початкова вартість.
 5  -- @param discount Частка знижки.
 6  -- @return Вартість після знижки.
 7  function calculator.calculate_price(price, discount)
 8      return price * (1 - discount)
 9  end
10
11  return calculator
У наведеному прикладі @param використовується для опису параметрів функції, а @return – для пояснення результату її виконання.
Правильно оформлена документація полегшує повторне використання функцій, ознайомлення з програмою нових розробників та подальше розширення проекту.
3.7 Особливості стилю програмування Lua
Мова Lua має декілька характерних особливостей, які необхідно враховувати під час оформлення програмного коду. Порівняння областей видимості зображено на рисунку Б.9.
До основних рекомендацій належать:
* використання local для змінних і функцій, які не повинні бути глобальними;
* логічне розділення функціональності на модулі;
* використання таблиць для організації пов'язаних даних;
* дотримання послідовного стилю іменування;
* уникнення надмірної вкладеності умовних конструкцій;
* використання інструментів автоматичного форматування та аналізу.
Особливо важливо контролювати область видимості змінних.
Небажаний приклад:
1  total = 0
2
3  function add_value(value)
4      total = total + value
5  end
У цьому прикладі total та add_value є глобальними, тому вони можуть впливати на інші частини програми.
Рекомендований приклад:
1  local total = 0
2
3  local function add_value(value)
4      total = total + value
5  end
Використання локальних змінних зменшує ризик випадкових конфліктів і робить залежності між частинами програми зрозумілішими.
На відміну від Python, де вкладеність блоків визначається відступами, або C++ і Java, де використовуються фігурні дужки, Lua застосовує ключові слова для позначення меж блоків. Тому відступи в Lua впливають насамперед на читабельність, а не на синтаксичну правильність програми.
3.8 Розробка на основі тестування (TDD)
Test-Driven Development (TDD) – це підхід до розробки програмного забезпечення, за якого тести створюються перед реалізацією відповідної функціональності. Процес TDD, описаний Кентом Беком у праці Test Driven Development: By Example, складається з трьох основних етапів [4]:
* red – створення тесту, який спочатку не проходить;
* green – написання мінімального коду, необхідного для успішного проходження тесту;
* refactor – покращення структури коду зі збереженням його поведінки.
Етапи підходу та інструменти автоматизації подано на рисунку Б.10.
У Lua для автоматизованого тестування можна використовувати фреймворк Busted.
Приклад тесту для перевірки додавання двох чисел:
1  local calculator = require("modules.calculator")
2
3  describe("Calculator", function()
4      it("adds two numbers", function()
5          assert.are.equal(8, calculator.add(5, 3))
6      end)
7  end)
У цьому прикладі перевіряється, чи повертає функція add() правильний результат.
Використання тестів дозволяє перевіряти коректність роботи функцій після внесення змін. Завдяки цьому розробник може впевненіше виконувати рефакторинг і виявляти помилки на ранніх етапах.
Для полегшення тестування рекомендується створювати невеликі функції з чітко визначеними параметрами та результатами, а також мінімізувати залежність від глобального стану.
3.9 Інструменти та автоматизація підтримки якості коду
Для забезпечення однакового стилю та підвищення якості програмного коду використовуються спеціалізовані інструменти автоматичної перевірки.
Для мови Lua можна застосовувати такі засоби:
* StyLua – автоматичний форматувальник коду Lua. Дозволяє забезпечити однакові відступи, розташування пробілів і структуру рядків відповідно до налаштувань проекту;
* Luacheck – інструмент статичного аналізу коду, призначений для виявлення потенційних проблем, зокрема невизначених глобальних змінних, невикористаних локальних змінних та інших підозрілих конструкцій;
* Busted – фреймворк для створення та виконання автоматизованих тестів;
* LDoc – інструмент автоматичного створення документації для програмних модулів та функцій Lua.
Для автоматизації перевірок можуть використовуватися Git Hooks та системи безперервної інтеграції (CI/CD), наприклад GitHub Actions.
Приклад команд перевірки проєкту:
1  stylua --check .
2  luacheck .
3  busted
Перша команда перевіряє форматування коду відповідно до правил StyLua, друга виконує статичний аналіз, а третя запускає тести за допомогою Busted.
Для використання цих команд відповідні інструменти мають бути попередньо встановлені.


Автоматизація перевірок дозволяє виявляти проблеми ще до об'єднання змін у спільному репозиторії та забезпечує дотримання єдиних правил оформлення коду.
3.10 Аналіз прикладів оформлення програмного коду
Для демонстрації впливу правил оформлення на читабельність було розглянуто два варіанти реалізації функції обчислення кінцевої вартості товару з урахуванням знижки. Візуальне порівняння наведено на рисунку Б.11, а
повний код – у прикладі В.2 додатка В.
Варіант до покращення має такі недоліки: 
* незрозумілі назви функції та параметрів;
* відсутність відступів для вкладених конструкцій;
* недостатньо зрозуміле призначення порогового значення 100;
* використання глобальної функції без необхідності;
* ускладнена підтримка та подальше розширення коду.
У покращеному варіанті використано зрозумілі назви, локальну функцію, іменовані значення та послідовні відступи.
Також було спрощено умовну конструкцію: після повернення значення всередині if немає необхідності використовувати else.
Обидва приклади для наведених вхідних даних повертають однаковий результат – 180. При цьому в другому варіанті структура програми є зрозумілішою, а зміна порогового значення або розміру знижки не потребує пошуку відповідних чисел усередині функції.
Таким чином, дотримання правил оформлення програмного коду сприяє підвищенню його читабельності, спрощує внесення змін і полегшує спільну роботу розробників.

На прикладах програмного коду продемонстровано застосування розглянутих рекомендацій та проведено порівняння правильного й неправильного оформлення. Встановлено, що використання зрозумілих назв, послідовних відступів, локальних змінних і логічного поділу програми на модулі сприяє підвищенню читабельності та полегшує подальшу підтримку коду.
Також було розглянуто основи розробки на основі тестування та інструменти StyLua, Luacheck, Busted і LDoc, які використовуються для автоматизації форматування, аналізу, тестування та документування програмного коду.        
Отже, дотримання єдиних правил оформлення коду є важливою складовою забезпечення якості програмного забезпечення, оскільки спрощує командну розробку, внесення змін та виявлення потенційних помилок. Підсумкові результати узагальнено на рисунку Б.12 додатка Б.
